## 1. 概述

### 1.1 背景

在 Windows 上做文件完整性校验，通常要先装一个哈希小工具（类似 `keir.net/hash.html` 的单文件程序）；而做 Base64 解码、时间戳换算或生成 UUID 时，又得打开网页或另装工具。

`hash` 把「批量文件哈希」这一核心能力做扎实，同时把日常工作中最常用的十个小工具收进同一个离线程序：一次启动、一个快捷键、不联网、不要管理员权限、不上传任何内容。

### 1.2 产品目标

| 目标       | 含义                                                         | 主要承载需求                     |
| ---------- | ------------------------------------------------------------ | -------------------------------- |
| **可信**   | 文件校验结果是唯一权威输出：可被机器消费（TSV/JSON）、可人工比对（宽松摘要粘贴）、可原子落盘 | FR-HASH、FR-FMT、FR-ATOMIC、FR-CMP |
| **快且不抢资源** | 每个文件只读一次、扇出给全部算法；满载计算时前台窗口与其他程序不受影响 | FR-ENG-4、FR-BATCH-9、NFR-PERF    |
| **零负担** | 纯离线、无需管理员权限、不上传文件内容；发布目录经裁剪，体积可控 | NFR-SEC-1/2、NFR-PERF-5/6/7       |
| **一致**   | CLI 与 GUI 共用同一摘要引擎与注册表，同一输入在两端结果相同   | FR-X                             |

### 1.3 非目标

- 只做摘要与校验，不做加密、解密、签名。
- 不做云同步、账号、遥测、自动更新。
- 不做安装包（无 MSI、无代码签名），仅提供免安装 zip。
- 不承诺 MD5 / SHA-1 / CRC / Adler-32 / FNV 的密码学安全性，它们只用于兼容、错误检测与非加密场景。
- v1.x 中 CLI 不从 stdin 读取文件内容（未来方向见 §9）；GUI 不接受命令行参数。

## 3. 功能需求

### 3.1 摘要引擎（FR-ENG）

| 编号     | 需求                                                         | 优先级 |
| -------- | ------------------------------------------------------------ | ------ |
| FR-ENG-1 | 内置 20 种算法，分四类：密码学 6 种（`sha224`、`sha256`、`sha384`、`sha512`、`sha512-224`、`sha512-256`）；传统兼容 2 种（`md5`、`sha1`）；校验和 6 种（`adler32`、`crc32-ieee`、`crc32-castagnoli`、`crc32-koopman`、`crc64-ecma`、`crc64-iso`）；非加密哈希 6 种（`fnv1-32/64/128`、`fnv1a-32/64/128`） | P0     |
| FR-ENG-2 | 标准摘要由 Qt `QCryptographicHash` 计算；`adler32`、全部 CRC、全部 FNV 以及 `sha512-224/256` 为项目内置实现 | P0     |
| FR-ENG-3 | 全部算法通过标准测试向量校验（`tests/test_registry.h: standardDigestVectors`）；SHA-512/t 的截断值跨调用稳定 | P0     |
| FR-ENG-4 | 每个文件**只读一遍**，一次读取扇出给全部请求的算法（`oneReadComputesEveryRequestedAlgorithm`） | P0     |
| FR-ENG-5 | 算法名不区分大小写，统一归一为小写；未知算法返回明确的哨兵错误（`validateAlgorithms`） | P0     |
| FR-ENG-6 | 每个文件新建 digester 实例，算法之间不共享增量状态           | P0     |
| FR-ENG-7 | 注册表是算法名称、展示标签、类别与「是否适合安全用途」标记的唯一来源。该标记经 `AlgorithmsModel` 的 `secure` 角色暴露给 QML，算法 chips 在 `secure === false` 的算法（md5、sha1、全部校验和与 FNV）旁显示 `⚠` 与中文提示；CLI 不呈现该标记 | P0     |

### 3.2 单文件哈希不变量（FR-HASH）

| 编号      | 需求                                                         | 优先级 |
| --------- | ------------------------------------------------------------ | ------ |
| FR-HASH-1 | 先 `Open`，再对**句柄** stat，不留 `Lstat → Open` 的 TOCTOU 窗口 | P0     |
| FR-HASH-2 | 跟随符号链接；拒绝非普通文件（目录、FIFO/管道、设备），且不因 FIFO 而阻塞（`fifoIsRejectedWithoutBlocking`） | P0     |
| FR-HASH-3 | 哈希结束后对句柄与路径各 stat 一次，比较大小与 mtime，产出「已变化」标记（`changedDetectsModificationDuringHashing`）；CLI 侧在 text 输出中补一行 `WARNING: file changed while hashing: <引号路径>`、JSON 中补 `"changed": true`，摘要与退出码不受影响（见 FR-FMT-1/4） | P0     |
| FR-HASH-4 | 流式读取，不把整个文件载入内存；正确处理 0 字节文件与缓冲区边界（`emptyFile`、`largeInputAndBufferBoundaries`） | P0     |
| FR-HASH-5 | 失败以空/非空字符串或 bool+出参返回，不用异常做控制流        | P0     |

### 3.3 批量编排（FR-BATCH）

| 编号       | 需求                                                         | 优先级 |
| ---------- | ------------------------------------------------------------ | ------ |
| FR-BATCH-1 | 结果**按请求顺序**返回，与完成先后无关（`preservesInputOrderAndReportsProgress`） | P0     |
| FR-BATCH-2 | 并发度默认 `min(4, 硬件并发数)`，可用 `--workers` 覆盖，硬上限 64；`--workers` 大于 64 时**截断到 64**（不报错）。*理由：再多只会增加栈内存与磁盘寻道争用* | P0     |
| FR-BATCH-3 | 单个文件失败不中止整批，失败项带错误继续（`continuesAfterMissingFile`） | P0     |
| FR-BATCH-4 | `FailFast` / `--fail-fast`：首个错误即设置取消标志并跳过剩余文件；被跳过的文件计为**失败**而非取消 | P0     |
| FR-BATCH-5 | 取消通过共享的 `std::atomic<bool>` 实现，在文件之间与读取块之间轮询；被取消的文件保留 `Canceled` 状态，已完成的结果保留 | P0     |
| FR-BATCH-6 | 始终满足 `CompletedBytes + CurrentBytes = 已哈希字节数`；文件开始时 Current 归零，完成时计入 Completed 并将 Current 归零 | P0     |
| FR-BATCH-7 | 进度快照不可变、不引用内部状态，接收方可留存；回调可能在多个线程并发触发 | P0     |
| FR-BATCH-8 | 单个文件结果最终确定时**立即**回调一次 `fileFinished`（并发场景同样适用） | P0     |
| FR-BATCH-9 | Windows 下 worker 线程以 `THREAD_PRIORITY_BELOW_NORMAL` 运行，满载时不抢占前台 | P0     |

### 3.4 CLI（FR-CLI）

用法：`hash.exe [options] <file-or-pattern>...`

| 编号      | 需求                                                         | 优先级 |
| --------- | ------------------------------------------------------------ | ------ |
| FR-CLI-1  | `-a/--algorithm <list>`：逗号分隔，逐项去空白并转小写；未指定时默认 `sha256` | P0     |
| FR-CLI-2  | `--all` 选中全部已注册算法，优先级高于 `-a`                  | P0     |
| FR-CLI-3  | `--size` 追加文件大小；`--modified` 追加修改时间；`--utc` 使时间以 UTC 表示（语义见 Q-5） | P0     |
| FR-CLI-4  | `--workers <n>`：负数报用法错误；0 或未指定时使用默认并发    | P0     |
| FR-CLI-5  | `--format text\|tsv\|json`（不区分大小写），默认 `text`；非法值报用法错误 | P0     |
| FR-CLI-6  | `-o/--output <file>` 原子写入；被 Ctrl+C / SIGTERM 中断时**不写入**，原文件保持不变 | P0     |
| FR-CLI-7  | `--recursive` 递归处理目录；`--literal` 关闭通配符展开       | P0     |
| FR-CLI-8  | 单横线与双横线等价（`-a` 与 `--algorithm`）；支持 `--flag=value`；`--` 之后的参数全部视为路径 | P0     |
| FR-CLI-9  | 布尔标志接受 `1/t/T/true/TRUE/True` 与 `0/f/F/false/FALSE/False` | P0     |
| FR-CLI-10 | 未给出路径时报哨兵错误 `at least one file path or pattern is required` 并打印用法；目录未加 `--recursive` 时明确拒绝并给出提示（退出码见 Q-6） | P0     |
| FR-CLI-11 | Windows 下由程序自行展开通配符（shell 不负责展开）；排序与去重规则同 FR-PATH-5 | P0     |
| FR-CLI-12 | 按输入顺序流式写出，不在内存中积攒全部输出                   | P0     |
| FR-CLI-13 | `--version` 打印 `hash <版本>`；`-h/--help` 打印用法；二者都输出到 **stdout**，退出码 0 | P0     |
| FR-CLI-14 | 用法或解析错误输出到 stderr 并附用法文本，退出码 2           | P0     |
| FR-CLI-15 | stdout 写入失败（管道关闭、磁盘满）必须报错，不得谎报成功（`Fail when standard output cannot be written`） | P0     |

> CLI 的错误文本为英文哨兵串，属于兼容面（§7）；GUI 文案为中文（NFR-UX-1）。

**退出码契约（不可回退）**

| 码  | 含义   | 典型触发                                               |
| --- | ------ | ------------------------------------------------------ |
| 0   | 成功   | 全部文件成功；`--version`；`-h/--help`                 |
| 1   | 失败   | 任一文件出错；`--fail-fast` 跳过的文件；输出写入失败；路径不存在、模式无匹配、`--recursive` 遍历失败 |
| 2   | 用法错误 | 未知参数、非法 `--format`、负数 `--workers`、`at least one file path or pattern is required`、模式语法错误、目录未加 `--recursive` |
| 3   | 被中断 | Ctrl+C / SIGTERM                                       |

> 退出码不取决于哪个文件先失败。

### 3.5 输出格式（FR-FMT）

| 编号     | 需求                                                         | 优先级 |
| -------- | ------------------------------------------------------------ | ------ |
| FR-FMT-1 | `text`：每个算法一行 `算法 <TAB> 摘要 <TAB> 引号路径`，可选追加 `size=` / `modified=`；失败行为 `ERROR <TAB> 引号路径 <TAB> 引号错误`；发生变化的文件额外输出一行 `WARNING: file changed while hashing: <引号路径>`（每个文件一条，不影响退出码） | P0     |
| FR-FMT-2 | `tsv`：固定列头 `algorithm digest path error [size] [modified]`；可选列仅在请求时出现，列契约保持稳定 | P0     |
| FR-FMT-3 | TSV 单元格转义反斜杠、Tab、CR、LF；以 `=` `+` `-` `@` 开头的内容加 `'` 前缀防公式注入；占位符（`-`、`ERROR`、程序生成的数字/时间）**不加**前缀 | P0     |
| FR-FMT-4 | `json`：每个文件一个对象（而非每个算法一行）；摘要对象的键按算法名**排序**；出错的文件只带 `error` 字段，不带摘要；发生变化的文件在摘要对象前额外带 `"changed": true`（完整结构见 FR-FMT-8） | P0     |
| FR-FMT-5 | JSON 转义控制字符（`\u00XX`）、`<` `>` `&` 以及 U+2028/U+2029 | P0     |
| FR-FMT-6 | text/TSV 中的路径使用 `goQuote` 编码，保证可逆               | P0     |
| FR-FMT-7 | 支持的格式列表与 `unsupported output format` 错误来自同一常量，CLI 与格式层不会不一致 | P0     |
| FR-FMT-8 | `json` 的**外层是单个数组**（不是 NDJSON）；字段按固定顺序 `path`、`size`、`modified`、`changed`、`digests`、`error` 出现，可选字段仅在请求 `--size` / `--modified` 时出现，失败对象只含 `path` 与 `error`；空结果为 `[]`；末尾带一个换行。结构见下方示例与字段表 | P0     |

**JSON 结构（兼容面，见 §7）**

```json
[
  {
    "path": "C:\\Data\\a.bin",
    "size": 4,
    "modified": "2026-10-15T12:00:00",
    "changed": true,
    "digests": {
      "md5": "d41d8cd98f00b204e9800998ecf8427e",
      "sha256": "e3b0c442..."
    }
  },
  {
    "path": "missing.bin",
    "error": "open \"missing.bin\": no such file"
  }
]
```

| 字段       | 类型    | 出现条件                                       | 说明                                                         |
| ---------- | ------- | ---------------------------------------------- | ------------------------------------------------------------ |
| `path`     | string  | 恒有                                           | 请求路径（与 text/TSV 相同，不做 `goQuote`，直接 JSON 转义） |
| `size`     | number  | 仅当请求 `--size` **且**该文件成功             | 字节数                                                       |
| `modified` | string  | 仅当请求 `--modified` **且**该文件成功         | ISO-8601（`Qt::ISODate`）；`--utc` 时为 UTC 表示，否则为本地时间 |
| `changed`  | boolean | 仅当该文件在计算期间被改动（恒为 `true`）      | 摘要仍有效，与 text 的 `WARNING:` 行对应（FR-HASH-3）        |
| `digests`  | object  | 仅当该文件成功                                 | 键为算法名、值为摘要；键**按算法名排序**（与请求顺序无关）   |
| `error`    | string  | 仅当该文件失败                                 | 失败对象不含 `digests`；错误文本与 text 的 `ERROR` 行同源    |

### 3.6 原子输出与输入保护（FR-ATOMIC）

| 编号        | 需求                                                         | 优先级 |
| ----------- | ------------------------------------------------------------ | ------ |
| FR-ATOMIC-1 | 先写临时文件，再以 rename 替换；写入期间原文件始终可用       | P0     |
| FR-ATOMIC-2 | 拒绝写入目标为符号链接的输出                                 | P0     |
| FR-ATOMIC-3 | 拒绝把任何**输入文件**（含同一文件的别名，经 `pathKey` 判定）作为输出目标 | P0     |
| FR-ATOMIC-4 | 提交前重新校验目标，防止「早检查、晚提交」之间状态发生变化   | P0     |
| FR-ATOMIC-5 | 临时文件写入失败时报告**真实原因**（磁盘满、权限不足等），不吞成通用错误 | P0     |

### 3.7 摘要清单解析与比对（FR-CMP）

## 5. 约束与依赖

- **平台**：Windows 是唯一发布平台。Windows 专有行为（跳过 junction、`\` 作分隔符、worker 低优先级、`setColorScheme`）在其他平台必须降级或跳过（`Q_OS_WIN` / `QSKIP`）。
- **Qt 版本**：必须 6.8+（依赖 `setColorScheme`）。
- **CLI 参数解析**：刻意贴合 Go `flag` 包的语义（单/双横线等价、`--flag=value`、`-h` 成功退出）。这是历史兼容契约，不可随意改动。
- **发布体积**：「小」是产品属性，不是副产品。任何新增依赖（插件、样式、图片、翻译）都必须说明体积代价。
- **验证路径**：只有 CI（NFR-TEST-2）。

# 附录 A：UI 设计规范

本附录是 GUI 的设计规范，所有数值与令牌均取自实现（`Theme.qml`、`Main.qml`、各 `App*` 控件）。**新增界面必须复用这些令牌与控件。**

## A.1 设计原则

1. **唯一取色来源**：所有自定义表面的颜色、圆角、动画时长都来自 `Theme.qml`，页面中禁止出现裸色值。`Main.qml` 与 `main.cpp` 中的调色板只是平台兜底的镜像（见 A.3）。
2. **统一控件族**：可交互控件统一使用共享的 `App*` 组件，不直接用裸 `Button` / `TextField`，以保证各页结构一致。
3. **外壳常驻，内容懒建**：导航与状态栏永不重建；工具页首次打开时才创建并保活。切换工具只是切换视图，不是重开应用。
4. **键盘优先**：`Ctrl+K` 切换工具，`Esc` 回到概览；高频动作都有快捷键。
5. **状态双通道**：颜色（状态点）+ 文字（状态文案、计数）同时表达。
6. **字符即图标**：全部图标为单字符字形，零图片、零 SVG，兼顾体积与一致性（字形回退风险见 Q-13）。

## A.2 布局与尺寸

| 命令面板内 `↑` / `↓`                 | 移动当前项（循环）                         |
| 命令面板内 `Enter`                   | 打开当前项                                 |
| 命令面板内输入                       | 实时过滤（匹配名称、描述、关键字、类别、id） |

**反馈与状态**

- **hover**：颜色过渡 120 ms；可点击元素使用手型指针。
- **Toast → 状态栏**：所有操作结果（已添加 N 个文件 / 已复制 / 保存失败：…）都在状态栏显示，约 2.6 s 后复位。
- **忙碌态**：批量计算中禁用添加与清空，隐藏移除按钮，主按钮变为「取消」。
- **错误呈现**：字段级错误用 `danger` 文字就近显示（如 JSON 错误定位到行、颜色解析错误、时间戳解析错误）；跨页错误走 Toast。

**键盘与焦点**：时间戳页与进制页的 `AppTextField` 支持按 `Enter` 直接转换；命令面板打开时自动聚焦输入框，并重置查询与当前项。

**输入容错**

- Base64 解码容忍换行与空白，拒绝非法字符（含非 ASCII）。
- 粘贴宽松摘要时自动剥离 `sha256:`、`SHA-256：`、`md5 =` 等前缀。
- 颜色输入接受 `#RGBA` / `#RRGGBBAA`、CSS 百分比通道，以及 0–1 / 0–255 的 Alpha。
- 时间戳输入接受 ISO 8601、`yyyy-MM-dd HH:mm:ss`、`yyyy/MM/dd HH:mm:ss` 与仅日期。

## A.7 各页面布局（自上而下）

| 页面                    | 布局                                                         |
| ----------------------- | ------------------------------------------------------------ |
| **文件哈希**            | `PageHeader` → 算法 chips 行 → 文件队列卡片（`inset` 底 + `line` 边框 + `cardRadius`，内含 `ListView`；为空时居中显示引导文案；整卡覆盖 `DropArea`）→ 操作行（添加文件 / 清空；右对齐「N 个文件 · 已选 M 个算法」+ 主按钮）→ 进度条（仅运行中）→ 运行中提示 → 完成小结 → 比对计数 → 比对错误 → 结果操作行（复制 / 保存 / 粘贴对比 / 清除比对）→ 只读结果文本框（等宽、`NoWrap`） |

| **时间戳**              | 两个 `GroupBox`：①「时间戳 → 日期时间」：输入 + 秒/毫秒单选 + 转换 + 当前时间 + 错误 → 本地 / UTC / ISO 三行，各带 `⧉`；②「日期时间 → 时间戳」：输入 + 转换 + 错误 → 秒 / 毫秒两行，各带 `⧉` |

## A.8 视觉语言

- **层级靠明度**：canvas（最暗）→ surface → raised → inset（最亮），配合统一的发丝线（`line`）区分边界，尽量不用阴影。
- **强调只用一处**：`ice` 只用于图标、聚焦边框、进度、当前标记与链接；`iceDeep` 只用于选中/高亮填充。强调色不用于大面积背景。
- **状态双通道**：状态点颜色 + 状态文字；`已变化` 同时使用危险色与文字。
- **动效极简**：只有颜色/透明度的 120 ms 过渡与滚动条淡入；没有位移动画或弹跳，避免在批量计算时与主线程争用。
- **空态有引导**：空队列显示「把文件拖到这里」+ 操作提示；命令面板无匹配时显示「没有匹配的工具」。
- **文本密度**：次要信息（快捷键、类别、计数）用 11–12 px `muted`；机器产出（摘要、路径、UUID）一律等宽。

## A.9 反模式（Code Review 时直接打回）

- 在页面中写裸色值（如 `color: "#7AA2FF"`），或自定义圆角、时长。
- 用裸 `Button` / `TextField` / `CheckBox` 代替 `App*` 控件。
- 在 `Main.qml` 之外假设「页面在启动时已构建」（页面是懒加载 + 保活的）。
- 让命令面板复用侧栏的注册表实例（会改动侧栏列表）。
- 在 GUI 线程中做哈希或大文本处理（必须交给 `HashController` 或工具控制器）。
- 只用颜色表达状态而不同时给出文字。
- 错误呈现方式与既有模式不一致（字段级错误就近显示 `danger` 文字，跨页错误走 Toast + 状态栏）。
- 修改颜色时只改 `Theme.qml`，没有同步 `Main.qml` 与 `main.cpp` 的调色板镜像。
